# bunker-rs

Форк [itdoginfo/podkop](https://github.com/itdoginfo/podkop), в котором рядом с
sing-box можно выбрать второе ядро — [clash-rs](https://github.com/Watfaq/clash-rs).

Имя пакета, бинарника и конфига осталось прежним — `podkop`. Это не забывчивость:
так существующая установка обновляется поверх без миграции, а команды и пути в
чужих инструкциях продолжают работать. Своё имя носит только репозиторий.

**Ядро по умолчанию остаётся sing-box.** Пустое или неизвестное значение опции
считается им же, так что существующая установка ведёт себя ровно как раньше и
миграции не требует.

## Что проверено на железе

Ветка обкатана на **GL-XE300** (`mips_24kc`, ath79/nand, OpenWrt 25.12.5):
установщик сам определил платформу, скачал и поставил clash-rs 0.10.8, ядро
приняло сгенерированный конфиг, VLESS с Reality поднялся и отдал 154 мс.

> [!WARNING]
> **clash-rs не реализует uTLS.** В логе при старте:
> `client-fingerprint (uTLS) is not yet implemented, ignored`.
>
> Это значит, что TLS-отпечаток не мимикрирует под браузер. Reality
> подключается и работает, но против DPI, который смотрит на отпечаток,
> защита слабее, чем у sing-box. Переводить боевой роутер на clash-rs там,
> где VLESS уже прижимают, пока не стоит.

## Зачем

| | sing-box | clash-rs |
|---|---|---|
| размер бинарника | 38.6 МБ | 18–26 МБ |
| откуда берётся | пакет OpenWrt | скачивается подкопом |
| подписки | нет | штатные `proxy-providers` |

## Как переключить

clash-rs нет ни в одном фиде OpenWrt, поэтому его ставит сам подкоп:

```sh
uci set podkop.settings.core=clash-rs
uci commit podkop
podkop install_core
/etc/init.d/podkop restart
```

То же самое есть в интерфейсе: **Настройки → Proxy core**.

Откат на предыдущий бинарник ядра — `podkop rollback_core`.

## Что добавилось помимо второго ядра

Всё перечисленное работает на **обоих** ядрах, кроме подписок.

**Блокировка DNS-over-HTTPS.** Браузер с включённым DoH ходит к своему
резолверу напрямую по HTTPS и обходит маршрутизацию подкопа целиком:
пользователь думает, что сайты идут через туннель, а DNS утекает мимо.
Режется только порт 443 у известных провайдеров, поэтому обычный DNS и DoT
продолжают работать.

**Тип секции Bypass.** Отличается от Exclusion тем, что трафик вообще не
заходит в ядро — не получает tproxy-метку. Меньше нагрузки и меньше шансов
напороться на незрелые места ядра. Оговорка: правило работает по адресу
назначения, поэтому домены в такой секции требуют
`resolve_real_ip_for_routing=1`.

**Сторож ядра.** Главное в нём не перезапуск. Подкоп перенастраивает dnsmasq
на резолвер ядра, и если ядро упало, роутер теряет DNS целиком — не только
проксируемый трафик. Сторож сначала возвращает dnsmasq на системный резолвер
и только потом пытается поднять ядро.

**Подписки (только clash-rs).** Выражены штатным `proxy-providers`: ядро само
качает список серверов, обновляет его по расписанию и проверяет живость.
Своего парсера нет — если панель не отдаёт Clash-формат, подкоп об этом
скажет. Учтите, что clash-rs шлёт свой `User-Agent` (`clash-rs/<версия>`) и
переопределить его нечем.

## Разработка

```sh
sh tests/run.sh              # весь набор
sh tests/run.sh manager      # по фильтру имени
```

Тесты не требуют роутера и не ходят в сеть: модули устроены как чистые
преобразования, конфиг подаётся строкой и строкой же возвращается. Нужен
только `jq`; под Windows путь к нему задаётся переменной `JQ`.

CI гоняет набор **дважды** — под dash и под busybox ash. На роутере ash, в
ubuntu `/bin/sh` это dash, и расхождения между ними не теоретические: на них
уже ловились ошибки, зелёные под одной оболочкой и красные под другой.

Устройство и решения описаны в [docs/mapping.md](docs/mapping.md) —
соответствие схем sing-box и Clash, включая места, где эквивалента нет.
Разбор чужих форков и что из них стоит брать — в
[docs/forks-features.md](docs/forks-features.md).

# Podkop

Маршрутизация трафика для OpenWrt.

Направляйте нужные ресурсы в туннель, а остальное — напрямую. Открытое программное обеспечение на базе [sing-box](https://github.com/SagerNet/sing-box).

> [!WARNING]
> Проект находится в стадии бета-версии. Возможны ошибки, нестабильная работа и существенные изменения функциональности.

# Вещи, которые необходимо знать перед установкой

### Обновления и конфигурация
- При обновлении **обязательно** [очищайте кэш LuCI](https://podkop.net/docs/clear-browser-cache/).
- После обновления проверяйте конфигурацию — она может изменяться между версиями.
- При старте Podkop модифицируется конфигурация Dnsmasq.
- Podkop изменяет конфигурацию sing-box. Если вы используете собственную конфигурацию, заранее сохраните её.

### Системные требования
- Требуется OpenWrt 24.10 или выше.
- Необходимо минимум 25 МБ свободного места на устройстве. Устройства с флеш-памятью 16 МБ не поддерживаются.

### Важные ограничения и особенности
- Если установлен Getdomains, его [необходимо удалить](https://github.com/itdoginfo/domain-routing-openwrt?tab=readme-ov-file#скрипт-для-удаления)
- Dashboard доступен только при подключении по HTTP (из-за особенностей Clash API). При использовании HTTPS или домена работа может быть недоступна.

### Поддержка и диагностика
- [Руководство по диагностике](https://podkop.net/docs/diagnostics/)
- Актуальные изменения публикуются в [Telegram-чате](https://t.me/itdogchat/81758/420321). Пожалуйста, ознакомьтесь с закрепленными сообщениями.
- При возникновении проблем оставляйте технически грамотный фидбэк в GitHub Issues и Telegram-чате.
